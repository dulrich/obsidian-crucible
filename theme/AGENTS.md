# theme/ — N1 Console theme (Obsidian artifact, not bundled)

Local instructions for `theme/`. The root `AGENTS.md` is the canonical contract; this file adds
what is only true here. `theme/` is a **separate Obsidian artifact from the plugin** (`theme.css`
+ `manifest.json`, raw CSS, NOT bundled by esbuild) — it ships in-repo because the third
light/dark axis needs plugin JS to drive it.

Gates: the root Full Cleanup Loop applies. `npm run lint` runs Stylelint over `**/*.css`, which
includes `theme/theme.css`.

## Quirks

- **The N1 Console theme (`theme/`) and the plugin are a matched set — the plugin drives a *third* light/dark axis Obsidian doesn't natively have.** Obsidian only knows binary `.theme-dark`/`.theme-light` and runs one theme at a time, but the N1 Applied design system has a three-way **surround** (dark / med / light, Med default). A pure theme can't express the third state, so Crucible provides it: `applySurround` (`src/surround.ts`) writes `document.body.dataset.surround`, and `theme/theme.css` keys every token off `body[data-surround="…"]`. Consequences: (1) **`theme/` is a separate Obsidian artifact from the plugin** (`theme.css` + `manifest.json`, raw CSS, NOT bundled by esbuild; `main.js` is the plugin) — it ships in-repo because the switch needs plugin JS. (2) The surround is applied in `onload` **right after `loadSettings`, before the workspace paints** — moving it to `onLayoutReady` reintroduces a startup flash. (3) The switch commands live in the **`Appearance`** command group (union member in `main.ts`, `GROUP_ORDER` in `settings/sections/commands.ts`) and are `mutating: false` (chrome, not notes — they must never take the note lock). (4) **`applySurround` now owns Obsidian's base light/dark theme too, and this is a deliberate reversal of an earlier decision.** The original design left the semantic-var adapter mapped at plain `body` scope on the theory that specificity didn't matter and no internal-API call to flip the base theme was worth the version-fragility — both were wrong. **The specificity law:** Obsidian's `app.css` declares 55 CSS custom properties under `.theme-dark`/`.theme-light` at specificity **(0,1,0)**; a plain-`body` adapter is only **(0,0,1)**, and specificity beats source order unconditionally, so the adapter silently lost all 55 — including the `--color-base-*` ramp it appeared to map. Symptom: on Med surround every `--color-base-*`-derived surface rendered Obsidian's dark greys, buttons and form fields took base-theme colours on every surround instead of the theme's, and the tab-bar/titlebar strip flipped with the base theme via `--background-secondary-alt`. Fix: the adapter selector is now `body.theme-dark, body.theme-light` — specificity **(0,1,1)**, the minimum bump that outranks (0,1,0) — which only works if `<body>` always carries one of those two classes, which is what the base-theme alignment half of this fix guarantees. **Never write a new mapping at plain `body`.** Separately, CSS alone cannot reach surfaces that branch on the `theme-dark` class **in JavaScript**: mermaid's `filter: invert()`, the PDF viewer's `mod-themed` inversion, embedded tweets' `theme=dark` iframe param, and any third-party plugin calling `isDarkMode()`. So `applySurround(app, s)` also calls `alignBaseTheme`, which writes Obsidian's `theme` vault-config key (`obsidian` for Dark/Med, `moonstone` for Light) through the undocumented, presence-guarded `vault.getConfig`/`setConfig` — guarded like `SecretRegistry` guards `app.secretStorage`, and value-guarded (`getConfig('theme') !== want`) so an already-aligned base never re-writes and re-triggers Obsidian's `updateTheme()` flash. This takes a user off "Adapt to system" appearance the moment they set a surround. (5) **Block 1 and block 2 of `theme.css` both sit at (0,1,1), and stay non-colliding only by a strict name split**: block 1 (the three `body[data-surround=…]` token blocks) declares **only** `--n1-*` custom properties; block 2 (the adapter) declares **only** Obsidian-native names, every value a `var(--n1-*)` reference — never a per-surround literal inlined into block 2. Break that split and the two (0,1,1) blocks start fighting on source order. (6) **Exactly four `!important` declarations, and only those four.** Obsidian's `setAccentColor` (`app.js`) writes `--accent-h`, `--accent-s`, `--accent-l`, and `--text-on-accent` as *inline styles on `<body>`* whenever the vault has an `accentColor` set — inline beats any stylesheet rule regardless of specificity, so those four (and no others) carry `!important` in block 2 to seize them back for the surround. Consequence: Settings → Appearance → Accent color goes inert while this theme is active; change the accent by editing the three `--n1-accent-ui-*` triples in block 1 instead. A broader `!important` sweep is wrong — every other mapping already wins on specificity alone — and will be reverted. (7) **`--shadow-edges` is intentionally left unmapped.** `app.css` defines it only on `.theme-light`; hoisting a value for Dark/Med would add a shadow Obsidian never had there, not fix a gap. (8) The `--n1-*` values in `theme.css` are a **vendored snapshot** of the (mid-rename) design-system tokens (`7als_art_direction/packages/signalworks/css/tokens/*`); `theme/README.md` documents the source + re-vendor flow (a one-file edit of the three `body[data-surround]` blocks — do not add a build step or duplicate token files). Two accent families live in block 1 and must stay separate: `--n1-accent*` is the vendored brand signal orange, no longer consumed by the adapter; `--n1-accent-ui*` is the muted variant that actually drives Obsidian's links/toggles/selection/highlights — a re-vendor must not "fix" the adapter back onto `--n1-accent`. (9) The theme reskins Crucible's own UI **for free** because `styles.css` already consumes Obsidian semantic vars (`--background-primary`, `--text-normal`, `--interactive-accent`, …) — the adapter maps `--n1-*` onto those, so don't add N1-specific classes to plugin views. The Editorial reading-surface variant is a present-but-empty stub in `theme.css` block 3; populate it scoped to `.markdown-preview-view`/`.cm-editor` without touching the Console adapter.
