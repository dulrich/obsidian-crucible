# src/ingestion/ — Ingestion dashboard data, render & sections

Local instructions for the Ingestion dashboard's three layers: `data/` (pure row-computation
— blogs, channels, clippings, control centers, orphaned/missing attachments, transcripts,
uncaptured posts/videos, X posts), `render/` (cells, the sortable/keyed table primitive,
scroll-restore, echo-suppression, per-row controls), and `sections/` (one file per dashboard
section, composing `data/` + `render/`). The root `AGENTS.md` is the canonical contract;
this file adds what is only true here. User-facing writeup: `docs/ingestion-dashboard.md`.

Where the boundary sits: the queue/backend the dashboard reads job state from is
`src/orchestration/AGENTS.md`'s territory; this file covers the dashboard's own render
pipeline and its ID/attachment conventions.

## Quirks index

The one-line hooks below say *where to walk*, not what to do — read the full entry before acting.

- Derived ID frontmatter keys are kebab-case singular/plural pairs, derived from `source` only.
- Orphaned Attachments keys off the `_MD5` name convention, not a localize folder.
- The Ingestion dashboard renders through one dirty-set flush; `route()` drops queue-root paths and first-sightings; keyed tables reconcile rows in place; scroll restore is anchor-delta.

## Quirks

Non-obvious Obsidian/runtime behaviors that bit us once and would bite again. Add entries here when a fix turned out to hinge on something the API docs don't surface — and add them to the **nearest** `AGENTS.md`, not automatically this one.

- **Derived ID frontmatter keys are kebab-case singular/plural pairs**: `yt-video-id`/`yt-video-ids`, `post-id`/`post-ids`. The singulars are per-note metadata (one URL → one ID); the plurals are tracker-intake aggregates. `Lint: all` populates the singulars from the note's `source` field only — it never scans the note body, because the IDs are metadata about what the note represents, not about incidental URLs inside it. Existing notes with legacy snake_case keys (`video_ids`, `post_ids`) are migrated manually via `Lint: update property in vault`, which prompts for old/new key names and rewrites every frontmatter entry under `lintIgnoredFolders` filtering.

- **The Orphaned Attachments dashboard section keys off the `_MD5` name convention, not the localize folder.** There is no single "Localize directory" setting — `localizeAttachmentsFolderTemplate` is a per-note template (default `{{folder}}/_attachments/{{slug}}`), so managed attachments are scattered vault-wide. `computeOrphanedAttachmentRows` in `src/ingestion/data/orphanedAttachments.ts` therefore scans every vault file matching `MD5_NAME_RE` (exported from `src/localizeAttachments.ts`) of a localizable media type (`classifyLocalizeMediaType` in `src/utils.ts`), and flags those absent from `metadataCache.resolvedLinks`. Consequence 1: if a user changes `localizeAttachmentsNameTemplate` away from the `_MD5` suffix, their files won't be detected — keep the name template and the regex in sync. Consequence 2 (closed by pf-1): `resolvedLinks` covers embeds and body links but **not** frontmatter property links (`frontmatterLinks`), so the referenced set now also unions `getFileCache(f).frontmatterLinks` targets (resolved via `getFirstLinkpathDest`) — the same gap/fix shape as `buildLinkGraph` in `src/search/linkGraph.ts`; don't remove either half. Deletion uses `app.fileManager.trashFile` (vault trash), and "Cleanup all" routes through `ConfirmModal` (`src/confirmModal.ts`).

- **The Ingestion dashboard's render path is a filtered-events → dirty-set-flush → signature-skip → keyed-reconcile pipeline (rsp sprint), and each stage has a rule that must not regress.** (1) **`route()` early-returns for any path under `orchestrationQueueRoot`** — job files are real vault notes, so every enqueue/claim/settle/clear (renames fire route() twice, old+new path) used to trigger five full-vault-scan refreshes; no dashboard section reads job files, and queue UI updates arrive via the `orchestration-queue-updated` bus event instead (post thq WP-8 the guard matters most on deletion day — removing the ~20k-note frozen archive fires one vault event per note). (2) The `IGNORED_IDS_NOTE` block **returns** after consuming its echo markers (both the modify case and the first-ever-Ignore `vault.create` case used to leak a second render through the generic branches), and the meta branch's signature checks are `prev && …` — a **first sighting seeds the baseline without firing** (the path's due refresh already came from the unconditional structural branch on create). (3) Sections **compute rows before touching the DOM** (a throw leaves the previous render on screen, never a stuck "Scanning…"), and event-driven passes **skip all DOM work when the row signature is unchanged** (`computeRowSignature`/`shouldRepaint` in `src/ingestion/render/section.ts` — TFile refs collapse to `.path` in the replacer because a raw TFile is circular through Vault; live extras like in-flight badges fold in per-row, not whole-map). Forced passes (Refresh button, sort clicks, user actions) always repaint via `ctx.eventDriven`, which **only** the coordinated flush sets true — a structural test pins that to exactly one call site. (4) Vault/bus events **`markDirty(id)` into one `Set<SectionId>`** flushed by two `minIntervalGate` instances (FAST 150ms / SCAN 1000ms — leading-immediate + floored, chosen over rAF because the dashboard can sit in a backgrounded tab); `flushDirty` fires every dirty section synchronously in one batch so the scroll coordinator captures/restores once per batch. Don't reintroduce per-section debounces alongside it — the old ~10 trailing debounces all firing at the first quiet gap was the "four sections blank at once" bug. (5) Tables with a natural stable key pass **`rowKey`** to `renderSortableTable`, which reconciles `<tr>`s in place (cursor-walk `insertBefore`, `td.empty()` before every cell render so listeners never stack, duplicate keys logWarn + full-rebuild fallback, staleness guard self-heals after an external `body.empty()`); `renderTableSection` therefore no longer wipes its body every render — never add an unconditional container clear upstream of a keyed table, and never key rows by array index. `blogControl`/`channelControl` stay unkeyed until their own container-rebuild teardown is narrowed. (6) **Scroll restore is anchor-delta, not absolute** (thq WP-3, `src/ingestion/render/refresh.ts`): the coordinator captures `{el, offset}` via `offsetTop` at acquire and restores relative to the anchor when it is still connected (absolute fallback otherwise), so a Queue Monitor above the section changing height no longer drifts the viewport; a user scroll during the window cancels the pending restore. Known accepted nuance: the coordinator's *own* restore write can fire an async scroll event that false-cancels a subsequent re-assert — it degrades safe (toward native scroll anchoring), so don't "fix" it by suppressing user-scroll cancellation.
