## Context

Plan G validation left one defect and one feature request:

1. **"Lint: all" forever-hang (now non-reproducing).** User hit a permanent "Working…" spinner on a 0-byte note (earlier on body-without-frontmatter notes); it survived closing/reopening the note; a **full Obsidian restart cured it and it no longer repros** (zero-byte notes now lint cleanly). Investigation established: "Working…" is the note-lock overlay's fallback label — the palette's "Lint: all" runs `lint-note` under `command:lint-note` (unmapped → "Working…"), and the overlay is derived state, so a stuck overlay = a genuinely held lock. For the user's note shapes (both-absent: no block on disk, cache claims none) the g-4-adjacent paths **cannot wait at all** — the hang was a different mechanism. Leading theory (unprovable post-restart): **Obsidian's app-level per-file atomic write queue** (`processFrontMatter`/`vault.process` are contractually atomic per file, no client-side bound) **jammed by an op abandoned at plugin reload** — a plugin reload resets the in-memory `NoteLockManager` but not the app's queue, and a restart clears it; this fits every observation. Findings that stand regardless of mechanism: `NoteLockManager.acquire` has **no timeout ever** and waiters are invisible; the vault-wide lint loop is serial-await with **no try/finally** — one never-settling `lintFile` stalls the run and orphans the persistent Notice; and the **inverted asymmetry** g-4 left open (raw *has* a frontmatter block, cache claims *none* — first lint of a never-indexed file / second lint of a formerly-empty note) burns the full 2000 ms barrier per note, ×N across the serial loop.
2. **Feature:** surface "Search: audit index" as an Ingestion-Dashboard section with enqueue buttons for the repair actions, instead of command → report note only.

## Decisions locked

- User chose **full class hardening** for the lint/lock half (not instrumentation-only): watchdog diagnostics + slow-acquire diagnostics + overlay label fix + loop try/finally + the 2 s inverted-asymmetry residue fix.
- User chose a **new icon-table row: `wrench` = Repair** (enqueue repair/re-index job) — do not overload `play` (run-now) or `refresh-cw` (Refresh).
- No fix targets the unproven app-queue jam directly (unboundable from plugin code); the goal is that the **next occurrence self-diagnoses** in the debug log and degrades gracefully.
- Audit engine stays single-sourced: the command and the dashboard section share one runner; `src/search/audit.ts` stays pure (test-pinned: no `obsidian` import in its graph) — the extracted runner lives in a new I/O-side module.
- `mtimeOnly`/`unindexable` classes get **no enqueue affordance** (muted-with-title per the muted-never-absent law) — repair is a documented permanent no-op for them. Orphan deletion keeps `confirmDestructive('search-reconcile-orphans')` **inside the shared enqueue helper** so the dashboard cannot bypass it.
- The audit scan is expensive and unbounded on a cold index: the section is **forced-trigger only** (excluded from `FAST_SECTIONS`/`SCAN_SECTIONS`), with an explicit Run/Re-run control, cached result + "as of <time>" meta, and last-known/never-run/error empty-states.
