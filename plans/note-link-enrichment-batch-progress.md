# Plan J — Note-level link enrichment, batch-job progress, audit-Refresh cleanup

Repo: **obsidian-crucible** · slug `note-link-enrichment-batch-progress` · follows the tn-review 2026-08-02 remediation (closed at `c63fe43`). Born from user validation feedback after the remediation sprint.

*Recommended model/effort — Claude: Opus/medium J2, Sonnet/medium J1/J3/J4, orchestrator (Fable) closes J5 direct; Codex: Sol/medium J2, Terra/medium J1/J3/J4, Sol/medium orchestrator.*

## Context

Three user-reported gaps. (1) Batch-shaped jobs (`image_describe_batch` runs ~16+ min serial over 100 images) sit frozen in the queue monitor with a blank Progress cell — yet the plumbing is complete end-to-end (`progress` column in `jobs.sqlite`, `Orchestrator.setJobProgress`, coalesced 250ms `orchestration-queue-updated` repaint, a rendered Progress column) and only `search_upsert_batch` uses it, via a reach-through to `plugin.orchestrator`. (2) `link_scan` is vault-level only; YT enrichment keys off frontmatter `yt-video-id`, never off body links — a note referencing videos/X posts gets no enrichment, and video→channel chaining doesn't exist anywhere. (3) The Search Audit section's header Refresh button is confirmed dead chrome: it repaints the same closure-cached result and can never re-run the scan (the section's own never-scan-from-render law, pinned by tests).

## Decisions locked (user-confirmed 2026-08-02)

- **Progress: seam + all in-job loopers.** Add `reportProgress` to `WorkflowContext` (the documented widening pattern, like cancellation) and drive it from image batches, `link_scan`, and `search_sweep`; migrate the existing `SearchJobProgress` reach-through onto the seam.
- **`yt-metadata` promotes to a list** (mirroring list-valued `x-metadata`), verified safe: Refine/transcript workflows never read it (`_raw_transcript` exists only in unimplemented design docs); the read helpers are already array-tolerant. The user's caveat — video descriptions and metadata notes are URL farms — is handled by explicit self-guards and root exclusions (below).
- **Registry + jobs** for the note-level scan: incremental vault scan was investigated and rejected (a watermark leaks deletions/removals; doing it right is an audit-scale subsystem). The registry writer is lifted into a shared per-URL helper instead.
- **Hide Refresh on the Search Audit section** (buildSection opt-out); "Run audit" becomes the sole header action.

## Summary

Four dispatched WPs + close. J1 (progress), J2 (YT contract), J4 (Refresh) are mutually disjoint and run as wave 1. J3 (the note-level scan workflow) consumes J2's referenced-video mode and J1's touched `LinkScanWorkflow.ts`, so it runs as wave 2. Verified grounding from four Explore passes is pinned in the WP briefs — key reuse: `x_post_discover` already IS the note-level X scan; `extractUrls` + `canonicalizeUrl` classify YT/X/channel in one pass; `findExistingChannelAboutNote === null` is the "channel is new" test.
